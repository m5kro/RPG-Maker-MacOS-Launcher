# Windows用 MZベンチマーク

WindowsとmacOSを同じ計測処理で比較するためのツールです。ランチャー本体のWindows版ではありません。**Windows x64版の測定EXE**を含みます。Goのインストールは不要です。

## 用意するもの

- Windows 10/11 x64と標準のWindows PowerShell 5.1
- 自分が利用権を持つ、信頼できる展開済みのRPG Maker **MZ**ゲーム
- Windows版NW.js一式（`nw.exe`を指定）。MZゲーム付属のNW.jsベースの`Game.exe`も指定できますが、独自ラッパーや暗号化アーカイブ等の特殊な起動方式は対象外です。
- ゲーム全体のコピーとNW.jsプロファイルを保存できる空き容量。実行ごとにコピーが増えます。

ゲーム本体・RPG Makerの素材・NW.jsは同梱していません。NW.jsはEXEだけでは動きません。DLL等を含む元のフォルダのまま指定してください。MVには未対応です。

## 実行手順

1. ZIPを**ゲームフォルダの外**にある、書き込み可能な場所へすべて展開します。ZIP内から直接実行しないでください。
2. `Start-Benchmark.cmd`をダブルクリックします。管理者権限は不要です。
3. `index.html`と`js/rmmz_core.js`があるゲームフォルダのフルパスを入力します。これらが`www`内なら`www`を指定します。
4. Windows版`nw.exe`（またはNW.jsベースの`Game.exe`）のフルパスを入力します。空白・日本語を含むパスもそのまま入力できます。
5. 最初はモード`1`（Enterでも可）を選びます。ゲーム全体をコピーした後、自動で固定マップを起動します。コピー中は進捗バーがなく、大きなゲームでは時間がかかります。
6. ゲーム画面を前面に保ち、操作せず待ちます。10秒ウォームアップ＋30秒測定で自動終了します。フォーカスが外れると測定は最初からやり直しになります。
7. 表示された`results\日時-ID\report.zip`を返してください。同条件で2〜3回実行すると測定のばらつきも確認できます。

モード`2`は元プラグインを有効にした手動プレイ用です。タイトル表示等から60秒間のウォームアップ中に、セーブの読み込み等で対象場面に移動してください。その後30秒間、自動計測します。**対象場面に到着したことを検知して開始するわけではありません。** タイトルのままならタイトルが測定されます。何を測ったか（ゲーム名・マップ/戦闘・操作手順）を別途教えてください。開始・終了シーン名は結果に残りますが、すべての途中経過を記録するものではありません。

## 返すファイル

`report.zip`には以下だけを含めます。

- `result.json`：成功時のFPS、フレーム間隔、同期処理区間、実行版、画面情報
- `machine.json`：取得できたWindows版、CPU、RAM容量、GPU、ドライバー、解像度・リフレッシュレート
- `run-info.json`：固定/手動モード、ゲームフォルダ名、測定時間
- `console.log`：実行ログ
- `error.txt`など：失敗した場合の診断情報

**ゲーム・セーブ・プロファイルは返さないでください。** `run`フォルダにはコピーしたゲームとセーブ、プロファイルが含まれます。ログにローカルパスやゲームの出力が含まれることがあるので、共有前に確認してください。結果回収後、不要な各実行フォルダは手動で削除できます。

## 比較条件

- 同じゲーム・MZ版・データ・素材・解像度・画面モードを使用します。固定マップでも、タイルセットやパーティは元ゲーム由来です。別ゲーム同士の数値をそのまま比較できません。
- 固定モードは40×30マップに200イベントを置き、元プラグインを無効化します。実ゲームの互換性を検証するテストではありません。
- 既存のMac測定はMZ 1.8.0、NW.js **SDK 0.94.1 / Chromium 131**でした。OS差を調べる際は、可能ならWindowsも同じNW.js版・SDK種別に合わせます。異なる版でも測定できますが、版の違いを含む比較になります。実行中の版は結果に記録されます。
- ディスプレイは両方とも同じリフレッシュレート（まず60Hz推奨）にし、ブラウザ・録画・重いアプリを閉じ、同じ電源条件にします。機種やGPU性能差は残ります。
- `machine.json`のリフレッシュレートはWindowsが報告した値で、実際に使用したモニターや可変リフレッシュレートを厳密に確認するものではありません。
- 平均FPSだけでなくp95/p99も比較します。計測値にはVSync・スケジューリング・計測自体の負荷が含まれます。同期区間は重複し、GPU完了時間や厳密なCPU使用時間ではありません。

## 安全性と制約

ツールは入力ゲームを書き換えず、新しい出力先にコピーして計測します。既存出力は上書きせず、シンボリックリンク等の特殊ファイルは拒否します。ただし**コピーはサンドボックスではありません**。ゲーム/NW.jsは通常のユーザー権限で動きます。プラグインが絶対パスや独自保存先を使う場合、元セーブ等へアクセスできます。元のセーブは別途バックアップし、信頼できるゲームとNW.jsだけを実行してください。

起動スクリプトは、このPowerShellプロセスだけ`ExecutionPolicy Bypass`で同梱スクリプトを実行します。システム設定を恒久変更せず、外部ダウンロードも行いません。組織の実行制限は回避しないでください。EXEは未署名です。警告が出た場合は出所を確認し、セキュリティソフトを無効化しないでください。

macOS上でクロスビルドしており、Windows実機での起動・PowerShellの動作確認は未実施です。動かない場合は作成された`report.zip`、またはコンソールに出たエラーを返してください。通常は開始待ちを含め約160秒（手動モードは210秒）でタイムアウトしますが、ゲームのコピー時間は含みません。失敗しても途中のコピーが残ります。

## コマンドラインで実行する場合

PowerShellから（出力先の親フォルダは事前に作成、`run-01`は未作成にします）:

```powershell
.\benchmark-mz.exe --fixed --game 'D:\Games\MZGame' --runtime 'D:\NWjs\nw.exe' --root 'C:\Benchmarks\run-01' --warmup 10 --duration 30
```

この直接実行では`result.json`のみ生成され、機器情報や返送用ZIPは起動スクリプトで収集・作成します。

## ソースと再ビルド

同梱の`source`と`LICENSE`を参照してください。計測EXEはGo標準ライブラリのみを使用します。Go 1.26以降で、展開先から以下を実行できます。

```powershell
$env:CGO_ENABLED = '0'
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
go -C source build -trimpath -o ..\benchmark-mz.exe ./cmd/benchmark-mz
```

リポジトリからZIPを再作成する場合は`sh scripts/shell/build-windows-benchmark.sh`を実行します。
