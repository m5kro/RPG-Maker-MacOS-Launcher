# MZ フレーム間隔ベンチマーク

Windows x64向け測定EXE・ZIPの使い方とビルド手順は [windows-benchmark.md](windows-benchmark.md) を参照してください。計測スクリプトと固定ワークロードはmacOS版と共通です。

## 固定ワークロード

macOS の GUI セッションで `mise run benchmark` を実行します。`mise.toml` はプロジェクトルート基準の `build/validation/mz-20260717/` の展開済みゲームと `runtime/v0.94.1/nwjs.app` を環境変数の既定値に設定します。別の権利ある展開済み MZ ゲームと NW.js は環境変数で上書きできます（相対パスはプロジェクトルート基準）:

```sh
MZ_BENCHMARK_GAME=/absolute/path/to/game \
MZ_BENCHMARK_RUNTIME=/absolute/path/to/nwjs.app mise run benchmark
```

毎回 `build/benchmark-mz/run.XXXXXXXX/run/` に新規コピーと `result.json` を生成し、既存の出力は上書きしません。失敗した場合も途中のディレクトリは残ります。`build/` は Git 管理外です。入力を変更しませんが、ゲームのコピーには元のセーブ等も含まれます。十分な空き容量を用意してください。

固定ゲームはコピー上で元のプラグインを無効化し、自作 `workload.js` の 40×30 マップと 200 個の固定移動ルートイベントを MZ のマップ処理に渡し、自動で New Game を開始します。10 秒ウォームアップ後に Scene_Map のフレーム間隔を 30 秒測定します。ウィンドウを前面に保ち、操作しないでください。イベントの自律移動は画面近傍に限られる MZ 標準の処理です。画面解像度、タイルセット 1、開始パーティ、データベース、エンジンや素材は入力ゲーム由来です。タイル ID 2048〜2051 が有効なタイルセット、標準の MZ 起動方式と互換性のあるデータおよび素材が必要です。素材やバージョンが異なると見た目や負荷も変わるため、比較時には同一入力を使ってください。エンジン・標準素材・NW.js は含まず、配布もしません。

## 汎用計測器

信頼できる、自分で利用権を持つ MZ ゲームと NW.js を指定します。ゲームと runtime は配布・ダウンロードしません。Go と GUI セッションが必要です。

```sh
go -C src/go run ./cmd/benchmark-mz \
  --game /absolute/path/to/game --runtime /absolute/path/to/nwjs.app \
  --root /absolute/path/to/new-result --warmup 10 --duration 30
```

`--game` は `index.html`, `js/main.js`, `js/rmmz_core.js` を含む展開済みディレクトリです。シンボリックリンクや特殊ファイルを含むゲームは拒否します。`--root` は親が存在する未作成のディレクトリで、ゲームの外に指定します。新規 root にゲーム全体とプロファイルを作り、コピーの HTML に計測スクリプトを追加します。既存 root や結果は上書きしません。失敗時も途中までのコピーは残るので確認して手動で削除してください。元ゲーム内のセーブもコピーされます。十分なディスク空き容量が必要です。

起動時にウィンドウのフォーカスを要求しますが、OS が許可しない場合は手動で画面を前面にしてください。フォーカスがないと MZ の Splash が進まず、開始待ちになります。必要ならウォームアップ中に New Game を選んでください（タイトル画面も計測対象になります）。Boot/Splash を抜けた、開始済みでフォーカスのあるシーンからウォームアップが始まり、指定秒数後に計測します。フォーカス喪失または未開始のシーンへの遷移を検出すると、計測を破棄してウォームアップからやり直します。計測終了時に NW.js は終了します。開始できない、終了前に閉じた、結果を書けない場合は失敗します。開始待ちを含むタイムアウトはウォームアップ＋計測＋120秒です。結果は `root/result.json` です。

**計測範囲:** フレーム間隔はゲーム画面の `requestAnimationFrame` コールバック間隔で、VSync、スケジューリング、他の負荷による停止を含みます。FPS はフレーム数÷実経過時間、パーセンタイルは nearest-rank です。開始・終了時のシーン名も記録します。\n\n`cpu_sections` は `SceneManager.updateScene`、`Game_Map.update`、`Graphics.app.render` の同期呼び出し前後を `performance.now()` で測った経過時間を、それぞれ呼び出し数・合計・平均・p95（ミリ秒）で出力します。`available: false` は対象メソッドが見つからなかったこと、呼び出し数 0 の平均と p95 は null を意味します。マップ更新はシーン更新に含まれるため合計を足してはいけません。他にも重複があり得ます。これは厳密な CPU 使用時間ではなく待機や割り込みを含み、GPU の実行・描画完了や非同期処理は測定できません。ラッパー・時計読み取り・サンプル保存・集計が負荷や FPS に影響するため、計測なしの性能と同一視しないでください。プラグインによるメソッド差し替え等は計測を妨げる場合があります。フレームや呼び出しごとの生データは保存しません。環境は NW.js/Chromium/Node のバージョン、OS種別・CPUアーキテクチャ、MZ版、画面サイズ等です。画面の前面状態、リフレッシュレート、ゲーム内の操作・設定を揃えない数値の比較はできません。ゲームのプラグインや特殊な起動方式・CSP により動かない場合があります。

コピーはサンドボックスではありません。NW.js とゲームのスクリプトには実行ユーザーの権限があり、元ゲームを含む任意のファイルやネットワークにアクセス可能です。信頼できないゲームを実行しないでください。通常の HOME は分離していません。ゲームが独自に保存先を指定する場合も保護されません。
